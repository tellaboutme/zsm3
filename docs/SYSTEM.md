# ZSM3 — архитектура системы (v1)

Статус: **проект на согласование**. Код пишется только после утверждения этого документа и ответов школы из раздела 15.

## 1. Цели и рамки

**Входит в v1**

1. Публичный сайт — новый фронтенд на Astro (статика).
2. **E-wniosek:** заявка на документ — продление или дубликат легитимации, _zaświadczenie o uczęszczaniu_ и т. д. Ученик проверяет статус по секретной ссылке, учётной записи у него нет.
3. **Panel** для персонала: секретариат обрабатывает заявки, учителя ведут галерею, администратор управляет доступами.
4. **Галерея:** альбомы по учебным годам, загрузка фото из панели, перенос архива (304 альбома, ~5 400 фото).

**Не входит в v1:** редактирование новостей из панели (новости остаются в `data/*.json` в git), онлайн-оплата, учётные записи учеников и родителей, замена BIP.

**Нефункциональные требования**

- Стоимость эксплуатации 0 zł в месяц на бесплатных тарифах.
- Соответствие RODO, закону о цифровой доступности (WCAG 2.1 AA) и OWASP ASVS 5.0 уровня 2.
- Ни один шаг конвейера не пропускается: изменение, не прошедшее все проверки, не попадает в `main`.

## 3. Общая схема

```
                        ┌────────────────── Cloudflare (аккаунт школы) ───────────────────┐
 Посетитель ──HTTPS──►  │  WAF (free managed rules) → Worker «zsm3-web»                    │
                        │     ├─ Static Assets: HTML/CSS/JS/шрифты/картинки сайта           │
                        │     ├─ /api/requests/*   публичный API заявок (Turnstile, лимиты) │
                        │     ├─ /api/gallery/*    чтение галереи (кэш на краю)             │
                        │     ├─ /media/*          фото из R2 (кэш, immutable)              │
 Персонал ──Access──►   │     ├─ /panel/*          статичные страницы панели                │
 (вход: SSO / OTP)      │     └─ /api/panel/*      API панели (JWT Access + роли + Origin)  │
                        │  D1 (eu)  — заявки, галерея, персонал, аудит                      │
                        │  R2 (eu)  — фото галереи                                          │
                        │  Queues   — исходящая почта (повторы, DLQ)                        │
                        │  Cron     — удаление по сроку, очистка                            │
                        └───────────────────────────────────────────┬──────────────────────┘
                                                                    └──► Brevo (EU) e-mail
```

Один Worker на одном origin: CORS не нужен, один деплой, одна политика заголовков. Статические файлы отдаёт сеть Cloudflare без вызова кода. Worker запускается только на маршрутах `/api/*`, `/media/*`, `/panel*` (`run_worker_first`).

## 6. Модель данных (D1)

Время хранится в UTC (`TEXT` ISO-8601), в интерфейсе показывается по `Europe/Warsaw`. Идентификаторы — UUIDv7. `PRAGMA foreign_keys = ON`, у каждого запроса есть индекс под его фильтр.

```
requests
  id                TEXT PK
  type              TEXT NOT NULL            -- из contracts: STUDENT_ID_RENEWAL | STUDENT_ID_DUPLICATE | ENROLLMENT_CERTIFICATE | …
  status            TEXT NOT NULL            -- submitted | in_progress | ready | collected | rejected | withdrawn
  pii_ciphertext    BLOB                     -- AES-256-GCM: {firstName, lastName, className|graduationYear, email, note}; NULL после удаления ПДн
  pii_key_id        TEXT                     -- NULL вместе с pii_ciphertext
  email_index       BLOB                     -- HMAC-SHA256(нормализованный email), для лимита открытых заявок; NULL после удаления ПДн
  pii_erased_at     TEXT
  CHECK ((pii_ciphertext IS NULL) = (pii_erased_at IS NOT NULL))
  status_token_hash BLOB NOT NULL UNIQUE     -- SHA-256 токена ссылки статуса
  staff_note        TEXT                     -- без персональных данных, для персонала
  created_at, updated_at, closed_at TEXT
  INDEX (status, created_at), INDEX (email_index, status), INDEX (closed_at)

albums
  id, school_year (TEXT '2025/2026'), slug UNIQUE(school_year, slug), title, description,
  cover_photo_id NULL, published_at NULL, deleted_at NULL, created_by, created_at, updated_at

photos
  id, album_id FK, position, width, height, alt, key_small, key_large, sha256 UNIQUE,
  deleted_at NULL, created_by, created_at
  INDEX (album_id, position)

staff
  email PK (нижний регистр), role (admin | secretariat | gallery_editor), active, created_at, updated_at

audit_log
  id, at, actor_email, action, entity, entity_id, details_json (без ПДн заявителя)
  INDEX (at)

outbox_failures
  id, message_kind, request_id, error_code, at   -- только то, что упало в DLQ
```

Миграции только расширяют схему (expand/contract): новая версия кода работает со старой схемой и наоборот. Применяются до деплоя Worker'а.

## 7. Потоки

### 7.1 Подача заявки

1. Страница `/e-wniosek` получает типы документов и их поля при сборке (из `contracts`). Динамического запроса за конфигурацией нет.
2. `POST /api/requests`, тело `application/json` не больше 8 КБ:
   1. проверка `Content-Type` и размера;
   2. лимит частоты: ключ = HMAC(IP, секрет), 5 заявок за 10 минут; IP не сохраняется;
   3. Turnstile `siteverify`: `success`, `hostname`, `action = "request"`, возраст `challenge_ts` не больше 300 с, `idempotency_key`;
   4. ловушка для ботов: скрытое поле пустое, форма заполнялась не меньше 3 с;
   5. `contracts.RequestInput.strict()` — discriminated union по `type`; NFC-нормализация, обрезка пробелов, лимиты длины, класс из списка;
   6. не больше 3 открытых заявок на один `email_index`;
   7. шифрование ПДн, генерация токена, `INSERT`;
   8. в очередь уходят два письма: заявителю (ссылка статуса) и секретариату (только номер и тип, **без ПДн**).
3. Ответ `201` со ссылкой статуса. Страница предлагает её сохранить, потому что в письме будет та же ссылка.

### 7.2 Проверка статуса

- Ссылка `https://<домен>/e-wniosek/status#<token>`. Токен — 32 случайных байта в base64url, лежит **во фрагменте URL**, поэтому не попадает в логи, `Referer` и историю прокси.
- Скрипт страницы отправляет `POST /api/requests/status {token}` (с лимитом частоты). Ответ: тип, статус, дата изменения, сообщение о выдаче. Персональных данных в ответе нет.

### 7.3 Отзыв заявки

`POST /api/requests/withdraw {token}`: статус `withdrawn`, ПДн удаляются сразу, остаётся обезличенная запись для статистики.

### 7.4 Панель: заявки

- `/panel/*` и `/api/panel/*` закрыты приложением Cloudflare Access. Вход через Microsoft 365 / Google Workspace школы (SSO с MFA), если они есть, иначе одноразовый код на e-mail из списка. Сессия 8 часов.
- Worker **сам** проверяет `Cf-Access-Jwt-Assertion`: подпись по JWKS команды, `aud`, `iss`, `exp`, `nbf`. Без валидного JWT ответ 401, даже если запрос как-то обошёл Access. Домен `workers.dev` и preview URL отключены.
- Роль берётся из `staff` (активная запись). Матрица доступа объявлена в коде одной таблицей и проверяется тестом для каждого маршрута.
- Изменяющие запросы требуют `Origin` = домен сайта и `Content-Type: application/json` (защита от CSRF).
- Переходы статусов проверяет машина состояний `domain/request-lifecycle`:
  `submitted → in_progress → ready → collected`, из любого открытого состояния → `rejected`. Заявитель получает письмо при `ready` и `rejected`.
- Каждое изменение пишется в `audit_log`.
- **Выдача документа только лично, после проверки удостоверения в секретариате.** Заявка онлайн — предварительное обращение. Поэтому подача заявки «от чужого имени» не даёт злоумышленнику никакого документа.

### 7.5 Панель: галерея

1. Редактор создаёт альбом (год, название, описание) и перетаскивает фото.
2. Web Worker в браузере декодирует файл (`createImageBitmap`, ориентация из EXIF), делает два размера — 400 и 1600 px по длинной стороне — и кодирует их в WebP через jSquash. При перекодировании пропадают EXIF и GPS.
3. Загрузка идёт по одному фото: `POST /api/panel/albums/:id/photos`, multipart из двух файлов, каждый не больше 1,5 МБ, с обязательным флажком «есть согласие на публикацию изображения».
4. Сервер **не доверяет клиенту**:
   - разбирает RIFF/WebP: разрешены только чанки `VP8 `, `VP8L`, `VP8X`, `ALPH`; `EXIF`, `XMP `, `ANIM`, `ICCP` и любые неизвестные отклоняются;
   - сверяет размеры из заголовка с допустимыми;
   - считает SHA-256; ключ R2 = `g/<sha256>-s.webp` и `g/<sha256>-l.webp`, путь от пользователя в ключ не попадает;
   - повторная загрузка того же файла распознаётся по `sha256`.
5. Альбом виден публично только после «Opublikuj». Удаление — мягкое (`deleted_at`), файлы из R2 убирает задача по расписанию через 30 дней.

### 7.6 Публичная галерея и медиа

- `GET /api/gallery/years`, `/api/gallery/years/:year/albums`, `/api/gallery/albums/:id`. Отдаются только опубликованные альбомы; ответы кэшируются на краю (`s-maxage=60, stale-while-revalidate=600`).
- `GET /media/g/<sha256>-(s|l).webp`: сверка с `photos` (альбом опубликован, фото не удалено), затем R2 → Cache API. Заголовки: `Content-Type: image/webp`, `nosniff`, `Cache-Control: public, max-age=31536000, immutable`, `Cross-Origin-Resource-Policy: same-origin`.
- **Импорт архива** выполняет `tools/import_gallery.py`: скачивание с текущего сайта (не больше 4 параллельных соединений), Pillow (поворот по EXIF, удаление метаданных, WebP 400/1600), загрузка в R2 по S3 API, генерация SQL для D1. Скрипт идемпотентен и продолжает с места остановки.

## 8. Безопасность

### 8.1 Модель угроз

| Угроза                     | Мера                                                                                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Спам и боты в форме        | Turnstile, лимит частоты, ловушка, лимит открытых заявок, WAF                                                                                                 |
| XSS                        | CSP без `unsafe-inline`, Trusted Types (`require-trusted-types-for 'script'`), запрет `innerHTML` линтером (`no-unsanitized`), только `textContent` и DOM API |
| SQL-инъекция               | только `prepare().bind()`; правило линтера запрещает шаблонные строки в `prepare`                                                                             |
| CSRF в панели              | проверка `Origin`, обязательный JSON, cookie Access `SameSite=Lax`                                                                                            |
| Обход Access               | собственная проверка JWT, отключённые `workers.dev` и preview URL                                                                                             |
| Повышение привилегий       | роли из БД, матрица доступа, тест на каждую пару «маршрут × роль»                                                                                             |
| Перебор токенов статуса    | 256 бит энтропии, лимит частоты, хранится только хэш                                                                                                          |
| Вредоносный файл           | собственный разбор WebP, белый список чанков, лимиты размеров, content-addressed ключи                                                                        |
| Утечка БД или бэкапа       | шифрование ПДн на уровне полей, ключ только в секретах Worker'а                                                                                               |
| Утечка через логи          | структурный логгер принимает только типизированные события без ПДн                                                                                            |
| Цепочка поставок           | lockfile, `minimumReleaseAge` 7 дней, OSV/audit, Actions закреплены по SHA, zizmor, SBOM                                                                      |
| Секреты в репозитории      | gitleaks в pre-commit и CI; `.dev.vars` в `.gitignore`                                                                                                        |
| Clickjacking               | `frame-ancestors 'none'`                                                                                                                                      |
| Отказ почтового провайдера | очередь с повторами и DLQ; заявка сохраняется независимо от почты                                                                                             |

### 8.2 HTTP-заголовки (на всё)

`Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`,
`Content-Security-Policy` — строгая, хэши inline-скрипта темы вычисляются при сборке, Turnstile и `youtube-nocookie.com` разрешены только там, где они используются,
`X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy` (всё выключено),
`Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`.
Для статики заголовки задаёт сгенерированный `_headers`, для ответов Worker'а — middleware. Набор заголовков проверяет тест. Цель на Mozilla Observatory — A+.

### 8.3 Криптография

- ПДн заявки — один JSON, AES-256-GCM (WebCrypto), случайный 96-битный IV на каждую запись, AAD = `request.id`. Ключ `PII_KEY_<id>` в секретах; `pii_key_id` в строке позволяет ротировать ключ без простоя.
- `email_index` = HMAC-SHA256 с отдельным ключом `EMAIL_INDEX_KEY`.
- Токены статуса: `crypto.getRandomValues`, в БД лежит только SHA-256.
- Панель расшифровывает ПДн только при выдаче конкретной заявки или страницы списка. Поиск по фамилии выполняется в браузере по уже загруженной странице.

### 8.4 Сроки хранения (значения по умолчанию, утверждает IOD)

| Данные                                         | Срок                                                  |
| ---------------------------------------------- | ----------------------------------------------------- |
| ПДн закрытой заявки (`collected`, `rejected`)  | 30 дней после закрытия                                |
| ПДн отозванной заявки                          | сразу                                                 |
| Открытая заявка без движения                   | 90 дней → `rejected` с письмом, потом по правилу выше |
| Обезличенная запись заявки (тип, даты, статус) | 2 года, для статистики                                |
| `audit_log`                                    | 2 года                                                |
| Логи Workers                                   | срок Cloudflare (несколько дней), без ПДн             |
| Удалённые фото                                 | 30 дней в R2, потом физическое удаление               |

Удаление выполняет Cron раз в сутки; каждый прогон пишется в `audit_log`.

## 11. Качество кода

### 11.1 Правила

- Комментариев в коде нет. Код объясняет себя именами и структурой. Это проверяют локальное правило ESLint `local/no-comments` для TS и тест на `tokenize` для Python. Исключение одно: `#!` в исполняемых скриптах.
- Нет `any`, `as` без проверки, `!` (non-null), `@ts-ignore`, `# type: ignore`, `noqa`. Отключать правила линтера в коде нельзя (`--no-inline-config`, `noqa` запрещён в настройках ruff).
- Внешние данные (запрос, строка БД, ответ Turnstile, JWT, env) разбираются схемой на границе. Внутри используются только типы.
- Ошибки: доменные ошибки — типизированные значения (`Result`), исключения только для действительно исключительных ситуаций. Ответы об ошибках — `application/problem+json` без стектрейсов.
- Время, случайность и ID передаются через зависимости (`Clock`, `Random`), поэтому тесты детерминированы.
- Глобального изменяемого состояния нет. Доменный слой чистый и не знает о Hono, D1 и R2.
- `switch` по объединениям исчерпывающий (`never`). Промисы не теряются (`no-floating-promises`).
- Файл до ~200 строк, функция до ~40. Цикломатическая сложность ограничена линтером.
- Коммиты в формате Conventional Commits; `main` защищена, изменения только через PR со всеми зелёными проверками.

## 12. CI/CD и эксплуатация

### 12.1 Конвейер (GitHub Actions)

```
PR ─► install (frozen lockfiles) ─► format · lint · types · no-comments
    ─► unit/integration + coverage ─► build ─► e2e + axe + Lighthouse (wrangler dev)
    ─► security: pnpm audit, OSV-Scanner (npm + uv), Semgrep (OWASP), CodeQL*, gitleaks, actionlint, ShellCheck, zizmor,
                 OWASP ZAP baseline по локальному серверу, SBOM (CycloneDX)
main ─► деплой preview (отдельные Worker/D1/R2, тестовые данные) ─► ZAP baseline по preview
     ─► ручное подтверждение (GitHub Environment «production») ─► миграции D1 ─► деплой
nightly ─► Stryker, ZAP full scan по preview, проверка зависимостей
```

\* CodeQL бесплатен только для публичных репозиториев (§15). У всех workflow `permissions: read-all` по умолчанию, actions закреплены по SHA. Токен деплоя Cloudflare ограничен правами Workers Scripts, D1 и R2 одного аккаунта.

### 12.3 Эксплуатация

- **Бэкапы:** D1 Time Travel (восстановление на момент времени) плюс еженедельный `wrangler d1 export` из GitHub Actions в приватный бакет R2, срок хранения 8 недель. ПДн в выгрузке уже зашифрованы на уровне полей.
- **Мониторинг:** Workers Logs, уведомления Cloudflare об ошибках, письмо администратору при сообщениях в DLQ.
- **Аварийный выключатель:** переменная `REQUESTS_ENABLED=false` закрывает приём заявок одним деплоем, вместо формы показываются контакты секретариата.
- **Инцидент с ПДн** (`docs/RUNBOOK.md`): выключить формы → ротировать ключи и токен деплоя → сообщить IOD сразу → IOD решает об уведомлении UODO в течение 72 часов.
- `/.well-known/security.txt` (RFC 9116) с контактом для сообщений об уязвимостях.
